' ===================== RELACIONAMENTOS: ATORES -> FRONTEND =====================
convivente --> frontend : Acesso a conteúdo\neducacional e comunidades.

curador --> frontend : Realiza a postagem e\nedição dos conteúdos\neducacionais.

moderador --> frontend : Revisa postagens e denúncias\nem uma comunidade. Pode\nrestringir ou banir conviventes.

administrador --> frontend : Pode cadastrar e gerenciar\nusuários e gerir conteúdos\ne comunidades já criados.

' ===================== RELACIONAMENTOS INTERNOS DO FRONTEND =====================
paginas --> servicos_http : Usa serviços para\nbuscar e enviar dados.

paginas --> componentes : Utiliza componentes\nvisuais reutilizáveis.

paginas --> estado : Consulta e atualiza\no estado da aplicação.

servicos_http --> interceptors : Requisições passam\npelos interceptors.

servicos_http --> modelos : Usa interfaces para\ntipar dados recebidos\ne enviados.

guards --> estado : Verifica autenticação\ne papel do usuário.

modulos_rotas --> guards : Aplica regras de acesso\nnas rotas protegidas.

modulos_rotas --> paginas : Direciona navegação\npara as views.

componentes --> modelos : Exibe dados tipados\npelas interfaces.

' ===================== FRONTEND -> BACKEND =====================
servicos_http --> backend : Chamada para a API\n(JSON/HTTP)\nRequisições feitas pelo\nfrontend para consumir\nos recursos da API.

' ===================== BACKEND -> BANCO E EXTERNOS =====================
backend --> banco : Leitura e gravação\nde dados (SQL)\nPersistência de todas as\ninformações da aplicação.

backend ..> google_auth : Comunicação para autenticação\nde usuários via Google\n(JSON/HTTPS)

backend ..> google_maps : Consulta mapas,\ngeocodificação e rotas\n(JSON/HTTPS)
